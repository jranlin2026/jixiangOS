# 飞鸽客户资料入OS与绿旗闭环设计

## 背景和目标

极享智能体客服需要把飞鸽订单事实和客户确认的联系方式安全录入极享OS，再保留订单历史备注、追加两行OS标准备注并把订单标记为绿色。本阶段保持客服确认，不自动发送聊天消息，不做无人值守全自动化。

闭环由两类权威事实共同驱动：飞鸽提供当前店铺、订单、平台商品、实付金额和付款时间；极享OS提供受控来源、店铺绑定、标准产品、销售分配和首次成功入库时间。插件只传原始页面事实和店铺绑定 ID，不决定来源、OS产品、销售或备注时间。

## 店铺、商品和来源规则

- 管理员先在“系统设置 → 产品设置 → 平台商品映射”创建店铺绑定，再为每个店铺维护平台商品名称、ID、SKU、别名到OS产品的映射。
- 同一个OS产品允许被多个店铺和多个平台名称映射。映射在店铺内隔离；同店铺的相同规范化别名不能同时指向不同OS产品。
- 匹配优先级是平台商品 ID → SKU → 当前店铺名称/别名 → 唯一OS产品完全同名。价格不参与匹配，不做模糊匹配后静默选择。
- 实付金额和付款时间来自当前飞鸽订单卡。OS价格只用于只读参考和差异提示。
- 未匹配商品允许录入，但OS产品字段保持为空，线索备注写`平台商品待匹配：<平台原名>`，同步审计保留原始名称。
- 资源归属固定为`公司资源`，来源固定为`抖音电商 / 飞鸽客服`，店铺由已选绑定派生。客服不能提交自由文本来源、店铺、OS产品或销售。
- 销售继续由极享OS线索流转分配；后端把实际`assignedTo/assignedToId`返回插件。未分配时备注显示`暂未分配`。
- 映射写入在同一数据库事务内对所属店铺行执行`FOR UPDATE`，并用锁内最新状态重新校验店铺存在且`active`；预检之后发生的删除/停用不得被并发写入绕过。

商品匹配预览是只读动作：不创建线索、不保存同步记录、不写飞鸽，只展示后端当前解析结果。平台商品名称、非负且最多两位小数的实付金额、有效付款时间是请求预览和入库的必填事实；缺失、空白、无效或无法唯一识别时必须失败关闭。多个启用店铺时客服必须选择；只有一个时可自动选中。店铺停用或页面店铺不一致会阻止入库。

客服点击完成时必须重读当前会话/订单，再用最新页面事实请求一次权威预览。最新商品 ID/SKU/名称、实付、付款时间、映射结果或价差结果与已展示快照任一不同时，本次停在写入前，界面换成最新快照并清除联系方式确认；只有客服重新核对、二次确认并再点击时才能继续。

## 联系方式与隐私边界

- 插件只从客户方向消息识别手机号或明确标注的微信号；识别不到时允许选择“站外已获取”并手工填写。
- 客户名固定使用飞鸽顶部抖音昵称，并将同一值同步保存到线索的“抖音昵称”字段。手机号和微信号至少一项，两项存在时都保存并都写入联系人备注行。
- 客服必须勾选“已确认昵称和联系方式属于当前订单”才能执行。
- 插件不会自动发送索号话术或任何聊天消息；推荐话术即使自动填入，也必须由客服确认后发送。

`browser_lead_syncs`不是客户主档，也不保存聊天全文。对新记录，为保证重试一致性，第一次成功事务会同时写入不可变的`completedAt`、销售分配快照，以及最小联系人快照：昵称和本次确认的手机号和/或微信号。这修正了旧设计中“同步表不重复保存手机号”的绝对表述。

`BrowserLeadSync.attemptToken`是单次入库执行权租约。新`PENDING`保留产生 token，`FAILED`或超时`PENDING`被原子抢占时必须替换 token。`markSucceeded/markFailed`只能以记录 ID + `PENDING` + 期望 token 条件写入；失去所有权时重读并返回当前记录。迟到的旧成功不能覆盖新`PENDING`，迟到的旧失败不能把`SUCCEEDED`降级。

新记录快照只用于基于第一次成功事实重建相同备注，以及在重复订单提交时检测资料冲突；不用于客户检索、重新计算销售或覆盖主线索，后续重试不改写。

迁移前已经`SUCCEEDED`且三个联系人快照字段都为`NULL`的旧行无法天然还原历史第一次成功事实。若它仍关联当前有效线索，仓储使用三个字段全空的条件更新原子回填一次当前线索联系人，然后重新读取数据库中的持久化胜者；并发调用不会各自返回不同本地视图。这个兼容路径得到的是“回填时当前线索资料”，不承诺等于历史首次成功资料。关联线索缺失/回收、快照残缺或格式不安全、`completedAt`缺失时，响应失败关闭并要求人工核对。快照仍是个人信息，必须按客户数据同级限制数据库、备份和导出访问，日志与验收报告不得输出完整联系方式。

## 标准备注和幂等合并

后端根据不可变联系人快照、OS实际分配销售和第一次成功的`completedAt`生成两行：

```text
#海盗船长/手机号：13800138000/微信号：jx888（对接：王小明）
#入OS（客服小李：2026-08-08 21:00）
```

仅手机号或仅微信号时只保留对应片段；没有负责人时使用`（对接：暂未分配）`。时间按`Asia/Shanghai`格式化为`YYYY-MM-DD HH:mm`，插件不能使用本机时间重建。

合并规则：

1. 保留原备注的字符、换行风格和行序，不替换或删除历史`#入EC`及其他内容。
2. 原备注非空且结尾没有换行时补一个换行。
3. 两条完整标准行分别判断，只追加缺失行。
4. 相同输入重复执行不产生重复行。
5. 昵称、联系方式、销售或入库时间含换行，或后端没有返回严格两行时，停止并要求先在OS清理。

## 执行顺序与页面验证

严格顺序是：

```text
重新读取并核对当前会话、唯一活动订单卡、已付款状态、店铺和必填订单事实
  -> 使用最新事实重新权威预览；变化则刷新界面并等待二次确认
  -> 极享OS解析并入库成功
  -> 打开唯一订单备注弹层并读取原备注
  -> 在写入前确认唯一绿色旗帜和唯一保存按钮
  -> 幂等填入备注并选择绿色旗帜
  -> 在同一弹层一次保存
  -> 同时验证备注摘要和当前绿色旗帜
  -> 上报平台完成结果
```

当前飞鸽把备注与订单标记放在同一保存动作内，所以页面实现不会先保存备注再发起第二次绿旗保存。它在任何写入前先验证所有控件，再合并备注、选择绿色并一次保存；只有弹层关闭、订单摘要包含全部备注行且绿旗被唯一确认时，才把两项都标记成功。

- OS入库失败：不打开备注弹层，不修改飞鸽。
- 打开弹层、定位控件或备注编辑器写入等发生在绿旗选择之前的失败：不点击绿色旗帜，不保存。
- 一旦绿色已经被选择，若保存控件变化、会话变化、保存调用或保存后验证失败，页面最终状态未知；客服必须手工核对飞鸽，系统只能记录失败/未知，不得报告成功或平台完成成功。
- 页面只接受明确绿色语义或已校准的`#00c87f`绿色图标，绝不按 radio 下标或 value 猜测；其他旗色不自动选择。

## 幂等、重复订单和异常状态

幂等键为`平台 + 店铺稳定标识 + 平台订单号`。重复订单不会创建第二条线索，并返回第一次成功保存的联系人、销售、入库时间、店铺和商品审计快照。

- 有效重复线索且资料一致：继续补齐未完成的平台动作。
- 资料冲突：返回`ORDER_CONTACT_CONFLICT`并列出昵称、手机号、微信号中的差异类型；不输出完整联系方式，不操作飞鸽。
- 线索在回收站：返回`LEAD_IN_RECYCLE_BIN`；先恢复原线索。确需重建时先永久删除，永久删除事务同步释放订单入库占用。
- 同步显示成功但原线索已不存在：本次联系资料与首次成功快照一致时自动重新获取订单入库租约并重建线索；快照冲突时停止。保留已成功的飞鸽备注和旗标审计，不重复操作。
- 店铺缺失、停用或页面名称不一致：停止并要求刷新、重新选择或修正绑定/别名。
- 商品配置冲突：停止并要求管理员修正；普通未匹配允许继续，且不伪造OS产品。
- 页面识别失败：客户、订单、状态、店铺、商品、金额、付款时间或控件无法唯一确认时停止，显示诊断。

## 重试、取消和退出

- OS已入库后的“重试订单备注和绿旗”复用`syncId`，不重新入库。备注合并仍幂等。
- 页面已完成、仅后端上报失败时，只重试上报，不再读取或点击飞鸽。
- 刷新识别、会话切换、店铺切换、新尝试取代旧尝试、关闭面板和退出都会取消旧尝试。取消后不继续入库、页面动作或成功上报。
- 页面动作已经发出后无法由JavaScript撤销；此时取消只阻止后续步骤和成功状态，客服必须人工核对飞鸽和OS。
- 退出开始前先取消活动尝试；退出成功仅接受`code === 0`且 worker 已完成本地退出。其他应用码或网络异常保留一致的已登录界面供重试，但不恢复已取消的旧完成尝试。任意认证请求的 HTTP 401 都是终态本地退出：worker 清除 token/操作人，UI清除已登录状态并要求重新登录。

## 自动测试与真实验收

自动测试必须覆盖：匹配优先级和价格禁用、跨店铺同产品、店铺行锁及锁内存在/active校验、未匹配录入、必填订单事实、最新点击重预览/变化后二次确认、来源派生、飞鸽金额/时间、`attemptToken`租约所有权、销售快照、两行备注、历史原文保留、幂等、回收站/孤立/资料冲突、店铺/页面歧义、失败短路、重试、取消、`code === 0`退出和401终态本地登出。

真实页面验收必须使用明确授权的已付款/已发货安全测试订单，并按下面顺序进行，失败即停止：

1. 核对店铺、订单、平台商品、实付金额和付款时间。
2. 核对映射OS产品；价格差异只提示。
3. 确认联系方式并入库，核对受控来源、店铺、产品、实付、付款时间和OS分配销售。
4. 核对原备注保留、标准两行、绿色旗帜和页面成功信号。
5. 重复点击，确认不重复创建线索或备注。
6. 用未映射商品确认OS产品为空、原名进入待匹配备注且平台仍可闭环。

自动测试、DOM夹具和本地构建不能证明管理员映射 UI 或飞鸽真实写入已被人工验收。手工发布门禁仅保留两项：管理员在安全OS环境完成店铺/映射 UI 验收；获授权真实飞鸽已付款/已发货订单分别完成 mapped/unmapped 全链路验收。当前文档不宣称两项已通过。真实 MySQL 双会话 live lock integration 可后续在受控数据库中补充，不作为额外手工发布阻断项。

## 本阶段不做

- 自动发送聊天消息。
- 无客服确认的全自动入库、备注和改旗。
- 三分钟自动计时并向售后群转发昵称。
- 自动拨打虚拟号。
- 自动处理灰、红、橙、蓝、紫旗帜。
- 从图片或语音中OCR识别联系方式。
