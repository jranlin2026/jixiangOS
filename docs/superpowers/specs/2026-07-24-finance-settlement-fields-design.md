# 财务中心分账字段统一设计

日期：2026-07-24
状态：已确认，待实施

## 1. 目标

统一财务中心“订单分账”和“售后挽回分账”的表格字段、视图设置与状态口径。默认表格以财务快速核款、分账、确认和发放为主，完整业务资料通过视图设置和详情弹窗按需查看。

本设计不改变订单审核、售后审核或提成计算规则，只调整财务工作台的信息组织和必要的数据聚合。

## 2. 统一原则

1. 两个分账页面统一使用以下财务状态：`待处理 → 待确认 → 待发放 → 已发放`，撤销后显示`已撤回`。
2. 财务页面不展示“已通过、已入库”等业务审核状态。
3. 默认字段只保留财务处理所需信息；手机号、微信、备注、审计时间等信息放入视图设置。
4. “操作”列固定在最右侧，不进入视图设置，不允许隐藏、拖动或冻结到其他位置。
5. 订单号或挽回订单号用于打开源业务资料；查看操作用于打开分账处理资料。
6. 保存分账、确认、撤回和删除成功后，表格行、状态统计和当前筛选结果必须立即同步。
7. 两个页面统一字段名称、状态颜色、按钮顺序、空值显示和详情分区。
8. 启用新的视图配置版本，避免旧浏览器配置污染新的默认字段和顺序。

## 3. 订单分账

### 3.1 默认表格字段

| 顺序 | 字段 | 展示要求 |
| --- | --- | --- |
| 1 | 订单号 | 可点击打开源订单资料 |
| 2 | 分账状态 | 使用统一财务状态 |
| 3 | 客户 | 显示客户名称 |
| 4 | 第三方平台订单 | 用于财务对账，空值显示 `-` |
| 5 | 产品名称 | 显示成交产品快照 |
| 6 | 产品等级 | 使用产品等级标签样式 |
| 7 | 实付金额 | 使用货币格式 |
| 8 | 官方收款渠道 | 使用订单保存值 |
| 9 | 付款时间 | 精确到分钟 |
| 10 | 销售负责人 | 使用订单销售负责人，不使用提交人替代 |
| 11 | 订单创建人 | 显示正式订单创建人 |
| 12 | 分账明细 | 显示角色、人员和金额摘要 |
| 13 | 分账总额 | 汇总当前有效分账金额 |
| 14 | 操作 | 固定最右侧 |

分账明细摘要格式：`销售：童双全 ¥300｜线索：林恩光 ¥100｜共 ¥400`。超过两项时显示前两项和“另有 N 人”，完整内容在分账详情中查看。

## 5. 分账详情布局

两个页面的分账详情统一分为以下区域：

1. **源业务资料**：订单或售后挽回订单的核心字段，字段名称与对应业务模块一致。
2. **付款资料**：实付或挽回成交金额、官方收款渠道、付款订单号、付款时间和付款截图。
3. **分账明细**：角色、人员、部门、提成方案、业绩金额、比例或固定金额、计算说明和分账金额。
4. **处理记录**：当前状态、分账经办人、保存时间、确认时间、发放时间、撤回人和撤回原因。

付款截图与成交路径或聊天记录必须分区展示，不合并成一个“凭证”字段。

## 6. 数据与兼容要求

1. 订单分账摘要需要稳定提供订单创建人、第三方平台订单、完整线索来源和付款订单号。
2. 售后挽回分账复用售后订单保存的原产品 ID、原产品等级快照、官方收款渠道、付款订单号和付款时间。
3. 分账总额只计算未撤回且未删除的有效分账明细。
4. 已撤回人数只统计处于撤回状态的明细，不与待分配人数混用。
5. 历史订单缺少新增字段时显示 `-`，不得用订单创建人、当前登录人或其他无关字段冒充。
6. 如果历史售后订单缺少原产品等级快照，可以按原产品名称读取当前产品等级作为显示回退，但不得反写历史订单。
7. 财务列表接口应直接返回所需摘要字段，避免前端逐行请求订单、人员或分账明细。

## 7. 实时更新与错误处理

- 分账变更成功后，前端使用服务端返回的最新记录更新当前行，并重新同步状态数量。
- 如果当前状态筛选不再包含变更后的记录，该行应立即从当前列表移除。
- 接口失败时保留原状态和原统计值，并显示明确错误，不做乐观假更新。
- 重复确认、重复撤回或处理过期状态时，服务端返回冲突错误，前端重新加载该行。

## 8. 验收标准

1. 两个页面默认字段及顺序与本设计一致。
2. 操作列始终固定最右侧，且不出现在视图设置中。
3. 所有默认字段和可选字段均能正确显示，不使用错误字段回填空值。
4. 订单分账和售后挽回分账使用完全一致的状态名称和颜色。
5. 保存、确认、撤回和删除后，行状态与顶部数量无需刷新页面即可正确更新。
6. 订单号可打开完整源资料，分账查看入口可打开完整分账资料。
7. 新旧数据均可加载；旧数据缺字段时显示 `-` 或使用规定的只读回退。
8. 视图设置支持显示、隐藏、排序、冻结和重置，并使用新的配置版本。
9. 表格、详情、接口和状态映射均有回归测试，TypeScript 检查、全量测试和生产构建通过。
