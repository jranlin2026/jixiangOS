# 极享商学院 P0 设计与实施边界

## 目标

极享商学院不是独立 LMS，而是极享OS内的课程运营闭环。第一阶段先确保一场课程能在系统中完成：课程建档、场次排期、课前准备、邀约到课、现场执行、课后跟进和课程复盘。

## 本轮已实现

- 课程库：课程编码、分类、目标、默认时长、版本 V1、草稿/启用/归档。
- 课程场次：课程、时间、场地、容量、负责人和状态流转。
- 执行清单：创建场次自动生成课前、课中、课后六项清单。
- 状态门禁：课前必做项未完成时，不允许进入“已就绪”。
- 客户参与：可关联当前账号有权查看的 CRM 客户，也允许临时录入尚未入库的学员。
- 运营记录：邀约、出席、课程互动、课程评估、课后跟进。
- 场次复盘：总结、问题、改进、指标和行动项的数据结构。
- 权限树：查看工作台、课程管理、场次运营、邀约与到课、课程复盘五项独立权限。
- 数据列表：课程和场次均使用服务端分页，并保留总数、页码、每页条数和跳页。

## 复用边界

- 客户和线索仍以 CRM 为唯一主数据，不建立商学院客户表。
- 订单、收款和权益继续由订单与财务域负责，商学院不自行确认付款。
- 课程资料后续应关联企业知识库，不复制文件存储能力。
- 课后销售动作后续应生成 CRM 待办或员工任务，不建立第二套任务系统。
- 课程 A/B/C 评估是单场课程反馈，不等同于客户等级、机会等级或生命周期。

## 等待业务确认但不阻塞底座的事项

1. 客户成功与售后在课程交接后的最终职责边界。
2. A/B/C 课程评估的正式定义和是否需要改名。
3. D1、D7、D30 跟进 SLA 与逾期规则。
4. 到课率、转化率、满意度等指标的正式分子与分母。
5. 课程权益与产品目录、已付款订单的自动校验规则。

## 下一阶段

- 课程大纲和资料从企业知识库引用。
- 从 CRM 线索与客户批量导入邀约名单。
- 将课后跟进生成 CRM 待办，并追踪 D1/D7/D30 完成率。
- 订单购买权益校验、核销与补课/转场处理。
- 讲师工作台、签到、问卷、证书等课堂工具。
- 按课程、场次、渠道、讲师和销售查看运营报表。
