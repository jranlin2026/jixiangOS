# 设备资产双 IMEI 设计

日期：2026-08-18  
状态：已确认

## 1. 背景与目标

当前设备资产使用单个必填 `imei` 字段，容易把“一个 IMEI”误解为“一台设备”。实际上，一台物理设备只应形成一条设备资产；单卡设备有一个 IMEI，双卡设备有两个 IMEI。

本次调整的目标是让新增、编辑、查询、详情、敏感字段查看及导入导出都遵循同一模型，同时兼容已有设备数据。

## 2. 领域规则

- 一条 `AssetDevice` 记录代表一台物理设备。
- 单卡设备必须填写 `IMEI 1`，不得填写 `IMEI 2`。
- 双卡设备必须同时填写 `IMEI 1` 和 `IMEI 2`。
- 同一设备的两个 IMEI 不得相同。
- 每个 IMEI 在全部设备的所有 IMEI 位置中全局唯一。
- IMEI 是设备硬件标识，不是 SIM 卡、手机号或手机号资产的标识。
- 设备数量按设备资产记录计数，不按 IMEI 数量计数。

## 3. 数据模型与兼容

设备资产使用两个明确且有顺序的字段：

```ts
interface AssetDevice {
  imei1: string;
  imei1Masked: string;
  imei2?: string;
  imei2Masked?: string;
}
```

旧记录的 `imei`、`imeiMasked` 在读取时归一化为 `imei1`、`imei1Masked`。兼容层允许旧数据继续被读取和编辑；新建及更新后的记录只以新字段为事实来源，不把一台双卡设备拆成两条记录。

旧客户端或旧导入数据提交的 `imei` 在过渡期作为 `imei1` 接收。服务端仍是全部校验的最终裁决者。

## 4. 新增与编辑

- 表单先展示 SIM 类型，再展示 IMEI 字段。
- `IMEI 1` 始终显示并必填。
- 选择“双卡”时显示并必填 `IMEI 2`。
- 从双卡改为单卡时，如 `IMEI 2` 尚未清空则阻止保存并给出明确提示。
- 如设备仍绑定卡槽 2 手机号，沿用现有阻止降为单卡的规则。
- 唯一性冲突应指出发生冲突的具体字段，不使用笼统报错。

## 5. 查询、展示与敏感信息

- 设备列表的 IMEI 列按两行展示 `IMEI 1`、`IMEI 2` 的掩码值；单卡设备只显示第一项。
- 关键词搜索同时匹配两个 IMEI 的掩码表示。
- 设备详情分别展示两个 IMEI，敏感字段逐项授权查看并写入现有审计日志。
- CSV 导出分别提供 `IMEI 1`、`IMEI 2` 两列。
- CSV 导入模板分别提供 `IMEI 1*`、`IMEI 2` 两列，并按 SIM 类型执行必填校验。

## 6. API 与校验

- 创建设备和更新设备统一调用同一套 IMEI 规范化与校验函数。
- 后端校验单卡/双卡必填关系、同设备重复、跨设备重复和掩码覆盖。
- 前端本地模式与后端模式保持相同校验语义，避免开发环境和生产环境行为不一致。
- 敏感字段接口可区分 `imei1` 与 `imei2`，不存在的 `imei2` 不返回空的敏感值。

## 7. 测试范围

- 单卡仅有 IMEI 1 时可创建。
- 单卡带 IMEI 2 时拒绝创建或更新。
- 双卡缺少任一 IMEI 时拒绝创建或更新。
- 同设备两个 IMEI 相同时拒绝。
- 任一 IMEI 与其他设备任一位置冲突时拒绝。
- 旧 `imei` 记录可正常读取、展示和编辑。
- 未授权用户只能得到两个 IMEI 的掩码值。
- 导入模板、导入校验、搜索、详情和导出覆盖两个 IMEI。

## 8. 不在本次范围

- 不增加 ICCID、IMSI 或 EID 字段。
- 不调整手机号资产与设备卡槽的现有关联模型。
- 不把 IMEI 建成独立子表。
- 不改变设备、手机号和互联网账号的数量统计口径。
