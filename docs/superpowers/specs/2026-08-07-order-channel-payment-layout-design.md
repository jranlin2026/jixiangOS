# 订单成交渠道与付款凭证布局设计

## 目标

解决提交订单时“订单类型”与“官方收款渠道”分属两个模块，导致公司自营小店的平台来源资料与订单业务信息割裂的问题。

## 页面结构

### 3. 订单与成交渠道

按以下顺序展示：

1. 订单类型。
2. 官方收款渠道。
3. 当官方收款渠道为“公司自营小店”时，展示来源平台、来源店铺和平台订单号。
4. 备注信息。

其他官方收款渠道不展示平台来源字段。

### 4. 付款与凭证

只保留实际付款事实和证明材料：

1. 实付金额。
2. 付款时间。
3. 付款订单号。
4. 付款截图。
5. 成交路径或聊天记录。

## 交互规则

- 新建订单默认按当前官方收款渠道决定是否显示平台字段。
- 选择“公司自营小店”后，来源平台、来源店铺和平台订单号必须填写完整。
- 从“公司自营小店”切换到其他渠道时，立即清空来源平台、来源店铺和平台订单号。
- 切换来源平台时，清空原来源店铺，避免平台和店铺错配。
- 编辑历史订单或执行订单更正时，如果已有平台资料，必须正常回显；只有用户主动切换到非自营小店渠道时才清空。
- 订单详情继续按已有字段展示平台资料，不新增第二套来源字段。

## 数据与兼容性

- 复用现有 `officialPaymentChannel`、`sourcePlatformId`、`sourcePlatformName`、`sourceShopId`、`sourceShopName` 和 `thirdPartyOrderNo` 字段。
- 不新增数据库字段，不改变订单、付款、提成和资金流水的数据模型。
- 新建订单、资料编辑和订单更正共用同一条件展示与清空逻辑。

## 校验与测试

- 公司自营小店缺少任一平台字段时阻止提交，并使用弹窗说明缺失内容。
- 非公司自营小店提交时不得携带隐藏的平台字段。
- 覆盖自营小店展开、渠道切换清空、平台切换清空店铺、历史订单回显和更正入口测试。
- 完成 TypeScript 检查、生产构建以及桌面端和窄屏表单验证。
