# 极享商学院独立模块 PRD V2.0

> 日期：2026-08-08
> 状态：视觉方向已选择，待页面方案确认
> 分支：`codex/jixiang-academy-p0`
> 产品定位：课程经营、客户转化与组织协同中心

## 1. 背景与结论

当前试作版将极享商学院放在企业标准中心内，并以课程库、课程场次和执行清单为主要能力。该版本只能验证基础数据模型与接口，不能承接极享商学院实际的周运营、课程研发、销售邀约、到课执行、课后转化和经营复盘。

V2.0 将极享商学院调整为左侧一级业务模块。企业标准中心只保存制度、SOP、模板和知识资产，商学院通过引用关系使用这些标准，不再作为企业标准中心的子页面。

## 2. 产品目标

### 2.1 业务目标

1. 让每周课程计划、负责人、目标和风险在一个工作台中可见。
2. 让每场课程从规划到复盘都有明确阶段、任务、截止时间和验收物。
3. 复用CRM客户数据完成邀约、确认、到课、分层和课后跟进，不建立第二套客户主档。
4. 将课程后的销售动作与订单、成交交接和客户成功流程连接起来。
5. 形成按课程、场次、销售、渠道和周期统计的经营漏斗。

### 2.2 成功标准

- 周三、周四课程可以在系统内完成计划、筹备、邀约、执行、分层、跟进与复盘。
- 所有关键动作有唯一第一负责人、截止时间、验收标准和操作记录。
- 课程结束后30分钟内可完成到课客户分层，A/B类客户24小时内产生销售待办。
- 成交后可关联正式订单，并在24小时内完成销售到客户成功的交接。
- 管理者可看到邀约、确认、到课、咨询、成交人数和成交金额的完整漏斗。

## 3. 非目标

本版本不建设外部学员门户、录播播放、学习进度、考试、作业、证书、公开报名站点和完整在线LMS。

## 4. 用户与职责

| 角色 | 第一责任 | 主要系统动作 |
|---|---|---|
| 商学院负责人 | 方向与经营结果 | 审批周计划、课程发布、风险处理、经营复盘 |
| 课程研发 | 课程内容与版本 | 大纲、PPT、案例、互动、版本归档 |
| 素材组 | 内容包装与传播 | 海报、朋友圈、短视频、直播视觉、课后素材 |
| 主讲人 | 课堂交付 | 查看锁版资料、授课、记录问题与反馈 |
| 销售 | 成交前客户Owner | 筛选客户、邀约、提醒、到课记录、分层、跟进、成交 |
| 销售主管 | 部门结果 | 查看本部门任务、客户漏斗、超期和转化 |
| 客户成功 | 成交后客户成长 | 验收交接、建联、激活、服务计划和风险 |
| 售后 | 产品开通与技术支持 | 接收技术问题、处理并回写结果 |
| 管理层 | 经营决策 | 查看全量经营结果、风险和复盘行动 |

## 5. 信息架构

左侧一级菜单新增“极享商学院”，默认进入 `/academy`。

| 页面 | 路由建议 | 核心任务 |
|---|---|---|
| 运营工作台 | `/academy` | 看本周课程、准备风险、个人待办和经营漏斗 |
| 课程计划 | `/academy/plans` | 制定周计划、课程任务书和经营目标 |
| 课程库 | `/academy/courses` | 管理课程、内容版本、课件和宣传资产 |
| 场次运营 | `/academy/sessions` | 管理每场课从筹备到复盘的阶段流程 |
| 学员与转化 | `/academy/engagements` | 邀约、确认、到课、分层、跟进、成交和交接 |
| 经营复盘 | `/academy/reviews` | 对比目标与实际，形成问题和改进行动 |

企业标准中心移除商学院业务入口，仅保留被课程引用的制度、SOP和模板。

## 6. 核心业务流程

### 6.1 周运营闭环

```text
周一课程规划
→ 周二内容、素材和邀约准备
→ 周三/周四课程执行
→ 课程后30分钟客户分层
→ T+1重点客户跟进
→ 成交后24小时交接
→ 周五课程与经营复盘
→ 优化项进入下一场或下一版本
```

### 6.2 课程状态

```text
草稿 → 内容审核 → 已锁版 → 已发布 → 已归档
```

锁版后的场次保存课程版本快照。课程库后续更新不得改变历史场次使用的内容版本。

### 6.3 场次状态

```text
课程规划 → 内容研发 → 素材准备 → 客户邀约 → 开课检查
→ 课堂执行 → 课后分层 → 销售跟进 → 课程复盘 → 已关闭
```

### 6.4 学员状态

```text
待邀约 → 已邀约 → 已确认/已拒绝 → 已到课/未到课
→ 待分层 → A类/B类/C类 → 跟进中
→ 已成交/暂缓/长期培育 → 已交接
```

## 7. 页面需求

### 7.1 运营工作台

采用已选定的“周课程作战台”视觉方向。

主要区域：

1. 本周课程计划：周一至周日，突出周三、周四场次。
2. 场次摘要：课程、时间、目标客户、第一负责人、准备状态和进入场次动作。
3. 准备风险预警：风险事项、关联场次、等级、负责人、截止时间和处理状态。
4. 本周转化漏斗：邀约、确认、到课、咨询、成交人数和成交金额。
5. 我的待办：任务、场次、类型、负责人、截止时间和超期状态。

不同角色按权限看到本人、本部门或全部数据。

### 7.2 课程计划

以周为主要工作单位，支持周视图与列表视图。

课程任务书字段：

- 课程名称、日期时间、目标客户、客户核心问题。
- 课程目标、核心观点、案例、互动设计、转化产品。
- 报名、到课、咨询、成交人数与成交金额目标。
- 总负责人、研发、素材、销售、主讲和现场保障负责人。
- 风险等级、计划状态、审批记录。

周计划发布后，可一键生成场次及任务模板。

### 7.3 课程库

课程列表使用极享OS统一表格、筛选和分页规范。

课程详情分区：

- 基本定位：目标人群、核心问题、课程目标、转化产品。
- 内容结构：大纲、核心观点、案例、互动和转化环节。
- 课程版本：版本号、状态、变更说明、创建人、审核人和发布时间。
- 课程资产：PPT、逐字稿、案例、海报、朋友圈文案、邀约话术、录像。
- 使用记录：使用该版本的历史场次和结果。

课程资产支持引用企业标准中心资料，但引用不转移资料所有权。

### 7.4 场次运营

场次详情采用独立全页，不使用超长弹窗。

顶部固定显示课程、版本、时间、地点、主讲、目标和总体状态。主体使用九阶段导航，每个阶段展示：

- 任务名称、第一负责人、协同人。
- 截止时间、验收标准、完成结果。
- 状态、风险、附件和操作记录。

开课检查必须覆盖：

- PPT与商业口径锁版。
- 宣传材料和邀约名单完成。
- 重点客户提醒完成。
- 直播账号、设备、网络、声音和备用方案通过。
- 课堂记录、客户问题记录和素材采集负责人明确。

存在红色风险时，不允许标记“准备就绪”，必须记录负责人和处理决定。

### 7.5 学员与转化

从CRM按权限选择客户，支持批量加入场次、批量邀约和批量提醒。

字段：

- 客户、公司、行业、来源、销售负责人。
- 邀约时间、邀约人、确认状态、未参加原因。
- 到课状态、课堂互动、问题、停留和购买信号。
- A/B/C分类、目标产品、下一步、负责人和截止时间。
- 跟进状态、正式订单、成交金额和交接状态。

课程互动写入客户动态，课后跟进复用CRM待办，不在商学院重复建立一套任务系统。

### 7.6 经营复盘

支持单场、周、月和课程版本维度。

核心指标：

- 邀约数、确认数、到课数、到课率。
- 互动数、咨询数、咨询率。
- A类、B类人数。
- 成交人数、成交金额、转化率和客单价。
- 跟进及时率、成交交接及时率。

复盘结构：目标与实际、差异、原因、购买原因、未购买原因、保留、停止、新增、改进行动。

每个改进行动必须有负责人、截止时间、验收标准和状态，并可关联下一场课程或下一课程版本。

## 8. 数据归属与集成

| 数据 | 主数据归属 | 商学院行为 |
|---|---|---|
| 客户和销售负责人 | 线索/客户管理 | 读取并写入课程互动和跟进动态 |
| 销售待办 | CRM待办 | 按分层结果自动创建和关联 |
| 正式订单与成交金额 | 订单管理 | 只关联，不复制订单主数据 |
| 付款资金 | 财务中心 | 只读取已确认资金结果 |
| 成交交接与服务 | 交付中心/客户成功 | 发起交接并读取状态 |
| 产品开通与技术问题 | 售后服务 | 生成或关联售后事项 |
| SOP、制度和模板 | 企业标准中心 | 引用指定版本 |
| 课程、场次、邀约、到课、分层和复盘 | 极享商学院 | 创建、维护并审计 |

## 9. 权限与数据范围

### 9.1 功能权限

- 商学院工作台查看。
- 周计划查看、创建、编辑、提交、审批和发布。
- 课程查看、创建、编辑、审核、锁版、发布和归档。
- 课程资产查看、上传、下载和删除。
- 场次查看、创建、编辑、执行、关闭和撤回。
- 学员加入、批量邀约、到课登记、分层、跟进和导出。
- 经营复盘查看、编辑、审批和导出。

### 9.2 数据范围

- 本人：本人负责的课程任务和本人CRM客户。
- 本部门：本部门人员、任务、客户和转化结果。
- 全部：全公司商学院数据。

课程内部资产权限独立于学员邀约权限。销售可邀约客户，不等于可下载全部PPT和逐字稿。

### 9.3 人员变动

员工调岗或离职后，未关闭任务、课程责任和学员跟进必须批量转交；历史操作人快照保留，不随员工资料修改而覆盖。

## 10. 核心数据模型

在现有Academy基础模型上增加或强化：

- `AcademyWeekPlan`：周目标、课程排期、审批和风险。
- `AcademyCourse`：课程主档。
- `AcademyCourseVersion`：锁版内容与历史版本。
- `AcademyCourseAssetRef`：课程资产或企业标准资料引用。
- `AcademySession`：场次、目标、课程版本快照和阶段。
- `AcademySessionTask`：阶段任务、负责人、截止时间、验收和风险。
- `AcademyEngagement`：客户在场次中的邀约、到课、分层和转化状态。
- `AcademyAttendance`：签到、到课和未到原因。
- `AcademyEvaluation`：课堂信号、问题和分类依据。
- `AcademyFollowUpRef`：CRM待办和客户动态的关联。
- `AcademySessionReview`：目标、实际、差异和复盘结论。
- `AcademyReviewAction`：复盘改进行动及验收。

## 11. 边界与异常

- 同一客户可参与多个场次，但同一场次不得重复加入。
- 客户负责人变化后，未完成课后跟进按CRM转交规则处理。
- 场次开始后不可更换课程版本；需要变更时必须保留变更记录和授权人。
- 已有课程互动或经营数据的场次不得物理删除，只能取消或归档。
- 取消课程必须记录原因，并处理已邀约学员和未完成任务。
- 到课与分层不得因场次关闭而丢失。
- 已成交金额以正式订单数据为准，禁止手工修改为另一口径。

## 12. 验收标准

### 场景一：创建周课程计划

Given 商学院负责人拥有计划创建和发布权限
When 创建周三和周四课程并填写目标、负责人和节点
Then 系统发布周计划并生成两个场次及对应阶段任务。

### 场景二：场次准备门禁

Given 场次仍有红色开课风险
When 负责人尝试标记准备就绪
Then 系统阻止操作，并显示未完成事项、负责人和截止时间。

### 场景三：销售邀约权限

Given 销售的数据范围为本人
When 从CRM选择学员
Then 只展示本人客户，并可批量加入场次和记录邀约状态。

### 场景四：课后分层

Given 学员已到课
When 销售将其标记为A类或B类
Then 系统要求填写目标产品、下一步和截止时间，并自动创建CRM待办。

### 场景五：成交关联

Given 学员已形成正式订单
When 商学院读取该客户的成交结果
Then 显示订单号和订单实付金额，并进入待交接状态，不允许手工改写金额。

### 场景六：经营漏斗

Given 本周存在多个课程场次
When 管理者查看运营工作台
Then 系统按完整筛选范围计算邀约、确认、到课、咨询、成交人数和成交金额，而非只统计当前页。

### 场景七：历史与审计

Given 课程版本、负责人或场次阶段发生变化
When 用户查看操作记录
Then 系统展示变更前后值、操作人、时间和原因。
