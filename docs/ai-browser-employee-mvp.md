# 极享AI浏览器员工 MVP

## 当前范围与安全边界

第一版只支持抖店飞鸽客服的协助式闭环：识别当前会话与订单、预览极享OS店铺/商品配置、由客服确认联系方式、创建或复用OS线索，再在同一个飞鸽订单中合并备注并选择红色旗帜。插件不会自动发送聊天消息，也不会取消联系方式确认。

执行前后都必须核对当前客户、订单和店铺。页面、店铺、订单、商品配置或控件存在歧义时，流程安全停止，不按位置、价格或相似文字猜测。

## 最终业务规则

1. 管理员必须先创建店铺绑定，再在该店铺下维护平台商品名称、商品 ID、SKU 和别名到OS标准产品的映射。客服不能用自由文本店铺标识创建线索。
2. 映射优先按店铺隔离：当前店铺的 ID、SKU 和名称/别名优先。当前店铺未命中时，如果公司范围内同名/别名映射唯一指向同一个OS产品，可复用该结果；指向多个OS产品时停止并要求管理员处理。
3. 商品匹配顺序固定为：当前店铺的平台商品 ID、SKU、已确认名称/别名，公司范围内唯一名称/别名映射，唯一的OS产品完全同名。价格不参与匹配，也不做模糊匹配。
4. 实付金额和付款时间只来自当前飞鸽订单卡。OS产品价格只作为参考和差异提示，绝不覆盖飞鸽事实。
5. 商品未匹配仍可录入。此时不写OS产品 ID/名称，插件显示“待匹配”，同步审计和线索备注保留平台原始商品名称。
6. 来源和店铺均由后端根据已选店铺绑定派生：资源归属固定为`公司资源`，来源固定为`抖音电商 / 飞鸽客服`。插件不能提交或覆盖来源、OS产品或销售人员。
7. 销售由极享OS现有线索流转规则分配，不由插件选择；没有负责人时备注写`暂未分配`。
8. 入库只强制要求当前客户昵称、平台订单号、已选绑定店铺、至少一项联系方式和客服确认。订单状态（包括已关闭）、页面店铺、商品、实付金额和付款时间缺失不阻断入库；但已识别的页面店铺与绑定店铺明确冲突，或已提供的金额/时间格式错误时仍会停止。

## 管理员配置

平台和店铺是全系统共用的唯一权威目录，不再在客户设置和插件配置中各建一套。管理员在极享OS依次打开：

1. “系统设置 → 产品设置 → 业务平台与店铺”，统一维护平台、店铺名称和启停状态。
2. “系统设置 → 产品设置 → 平台商品映射”，接入已有业务店铺并维护插件识别参数与商品映射。

新建插件店铺接入时必须选择已有业务店铺，不能再输入另一个自由文本店铺名。历史插件店铺只在平台和店铺名称唯一完全一致时自动归并；重名、模糊或跨平台情况必须由管理员在接入表单中手工选择。

### 1. 新增店铺与插件接入

先在“业务平台与店铺”新增店铺，再在“平台商品映射”点击“接入已有业务店铺”，填写：

- 业务平台 / 店铺：从权威目录选择，店铺名称和启停状态在权威目录统一修改。
- 稳定店铺标识：同一平台内唯一，创建后不可修改，例如`douyin-jixiang-intelligence`。
- 平台店铺 ID：有稳定 ID 时填写，可留空。
- 店铺别名：每行一个，用于核对飞鸽页面店铺名称。
- 来源：只读显示`公司资源 / 抖音电商 / 飞鸽客服`，不能由管理员或插件改成自由文本。

停用店铺后，插件运行时目录不再返回该店铺，也不能用它创建新线索；已有同步审计不被改写。

### 2. 新增平台商品映射

先选择店铺，再点击“新增商品映射”，填写平台商品名称、平台商品 ID、SKU、别名和一个已启用的OS标准产品。平台商品名称会自动纳入别名集合。

可按下面的验收样例配置：

```text
店铺：极享智能体
稳定标识：douyin-jixiang-intelligence
来源：公司资源 / 抖音电商 / 飞鸽客服
平台商品：淘金AI 多模态创作智能体 读书卡
OS产品：淘金AI
```

同一个`淘金AI`可以被多个店铺及多个平台名称映射。保存时会校验OS产品存在且启用；写入映射时在同一数据库事务内对所属店铺行执行`FOR UPDATE`，再以锁内最新状态校验店铺仍存在且`active`，防止并发停用/删除后还写入映射。同店铺别名冲突返回明确错误，不会静默覆盖。停用商品映射只把它设为停用，映射行和历史同步审计继续保留。

页面的店铺和商品结果均提供筛选、总条数、页码、每页条数和跳页；桌面表格与移动卡片使用同一份筛选与分页结果。

## 只读匹配预览

客服登录后，插件读取后端返回的启用店铺目录。只有一个店铺时自动选中；多个店铺时必须手工选择。旧版本保存的自由文本`shopKey`只会尝试一次唯一精确迁移，找不到或命中多个店铺时会被清除，不能继续提交。

选择店铺并识别到客户昵称和唯一订单号后，插件调用只读商品预览：它不创建线索、不写同步记录、不修改飞鸽，只返回权威店铺和可用的商品匹配结果。侧边栏展示绑定店铺、客户、订单、订单状态、平台商品、OS产品、平台实付金额和平台付款时间；店铺标题与下拉框使用同行布局。

点击“一键入OS并备注订单”时，插件必须重新读取当前会话/订单，并用当前能识别的商品、实付和付款时间再请求一次权威预览。客户、订单号、绑定店铺或已识别事实变化时安全停止，用最新快照刷新界面、清除联系方式确认，要求客服重新核对并二次确认后再点击；首次变化检测不入库、不操作飞鸽。

未匹配时显示：

```text
匹配产品：待匹配（本次仍可录入，平台原名会写入OS备注）
```

价格不同时显示：

```text
OS参考价 ¥299.00，仅供参考；本次按飞鸽实付 ¥399.00 录入
```

## 客服操作

1. 打开当前客户的唯一可见已付款、已发货、已完成或已关闭订单，在侧边栏点击“刷新识别”。已关闭（包括售后/退款完成）仍可作为客户线索入OS；状态未识别时可由客服核对后继续。明确为待付款、未付款、取消，或独立退款状态而非已关闭时停止。
2. 核对抖音昵称、订单号、订单状态、绑定店铺、平台商品和OS产品。客户、订单或多张活动订单卡存在歧义时不要继续。
3. 多店铺场景手工选择正确绑定；页面店铺未识别时使用人工选择的绑定，但页面店铺一旦被明确识别，必须与绑定名称或别名一致。
4. 使用从客户消息识别的手机号/微信号，或选择“站外已获取”后手工填写。手机号和微信号至少一项。
5. 勾选“我已确认昵称和联系方式属于当前订单”。该确认不可跳过。
6. 点击“一键入OS并备注订单”。插件先重新读取当前页面并重新权威预览；如果客户、订单或已识别事实变化，界面会刷新并取消原确认，客服必须二次核对和确认后再点击。
7. 查看“极享OS入库、订单备注、红色旗帜”三个状态。只有页面同时验证备注和红旗后才报告闭环成功。

话术库允许把内容填入飞鸽回复框，但始终由客服检查并点击发送；插件不会自动发送。

## 线索、同步审计与隐私

幂等键是`平台 + 店铺稳定标识 + 平台订单号`。线索创建继续调用极享OS的`customerCommandService.createLead`，沿用现有权限、查重、来源、销售分配和通知规则。

`browser_lead_syncs`不是第二份客户主档，也不保存聊天全文。它保存店铺、平台商品、匹配方式、实付金额、付款时间、处理状态等审计事实。对新入库记录，第一次成功事务会同时固化`completedAt`、OS实际分配销售，以及一份最小、不可变的权威联系人快照：昵称及本次已确认的手机号和/或微信号。

每个新建或从`FAILED`/超时`PENDING`重新抢占的入库尝试还会获得新的`attemptToken`租约。成功和失败回写都必须同时匹配同步记录 ID、`PENDING`状态和当前 token；旧尝试失去租约后只能重读当前记录，不能覆盖新`PENDING`或把`SUCCEEDED`降级为失败。

这份联系人快照是有意的有限重复，目的只有两个：重复点击时生成与第一次成功一致的两行备注，以及在主线索随后被修改时识别资料冲突。它不参与客户目录检索或后续资料覆盖，新记录首次写入后重试不会改写。

迁移前已经是`SUCCEEDED`但联系人快照三列都为空的旧同步记录是例外：只有仍能关联到当前有效线索时，仓储才会用条件更新原子地回填一次当前线索联系人，并重新读取持久化胜者。这个兼容回填不能保证还原历史第一次成功时的联系方式；关联线索缺失、在回收站，或快照/首次时间仍缺失、残缺或格式不安全时，系统失败关闭并要求人工核对，不能编造备注。由于快照仍包含个人信息，数据库访问、备份、导出和同步记录处置必须按OS客户数据同级保护；不得把快照写入日志、截图或验收报告。

## 订单备注和红色旗帜

后端根据首次成功入库时间、联系人快照和OS实际分配销售生成严格两行备注。手机号和微信号都存在时两项都写入：

```text
#海盗船长/手机号：13800138000/微信号：jx888（对接：王小明）
#入OS（2026-08-08 21:00）
```

没有销售时第一行使用`（对接：暂未分配）`。时间固定按`Asia/Shanghai`输出，重复入库沿用第一次成功时间。

合并规则：

1. 原备注的字符和行序原样保留，包括历史`#入EC`、销售姓名、卡密和退款原因。
2. 原备注非空且末尾没有换行时，只补一个与原文一致的换行符。
3. 仅追加缺失的完整标准行；两行分别判断，重复执行结果不变。
4. 插件不自行重建昵称、联系方式、销售或入库时间，也不新增旧格式`#入EC`。

平台动作的当前实现顺序是：重新核对会话和订单号 → OS入库成功 → 打开唯一备注弹层并读取原文 → 在任何写入前确认唯一红色旗帜和唯一保存按钮都存在 → 合并并填入备注 → 选择红色旗帜 → 在同一弹层一次保存 → 验证弹层关闭、备注摘要包含全部行且当前旗帜为红色。飞鸽把备注和订单标记放在同一保存动作内，因此二者作为一个页面提交验证。打开弹层、定位控件或写入备注等发生在选择红旗之前的失败不会点击红旗；一旦已经选择红色，若保存、会话复核或保存后验证失败，页面最终状态未知，客服必须手工核对飞鸽，系统不得报告成功或平台完成成功。

保存前，插件会取消勾选飞鸽的“自动添加备注人和时间到末尾”，避免再生成`[操作人 日期 时间]`。已经存在的历史签名不自动删除。

插件只接受明确的红色语义或当前已校准的红色`#ff3b52`图标信号，不按 radio 序号或 value 猜颜色。其他颜色继续由人工处理。

## 失败、重试、取消和退出

- OS入库失败或后端返回终止性冲突：不打开备注弹层，不修改飞鸽。
- 回收站线索：先在业务回收站恢复原线索；确需重建时，先永久删除原客户/线索，系统会在同一事务内释放对应订单的入库占用，然后可重新录入。
- 历史数据中同步显示成功但原线索已不存在：当本次联系资料与首次成功快照一致时，系统自动重新取得该订单的入库租约并重建线索；快照冲突时立即停止。已成功的飞鸽备注和旗标状态继续保留，不重复操作。
- 联系方式冲突：提示昵称、手机号或微信号中的实际差异；先在OS统一资料，再重新确认。提示和日志不显示完整联系方式。
- 店铺明确不一致或绑定已停用：刷新识别并选择正确启用绑定；仍不一致时由管理员修正店铺名称/别名。页面店铺未识别本身不阻断。
- 商品配置冲突：管理员修正同店铺映射后重新预览；未匹配不是冲突，可继续录入。
- 页面识别失败：客户或订单号缺失、多张活动订单卡、备注控件或红旗无法唯一识别时立即停止。商品、金额和付款时间未识别不阻断入库。
- 页面阶段失败：保留`syncId`和可复制备注。若失败发生在红旗选择前，插件未选择红旗；若已经选择红色后保存或验证失败，飞鸽状态未知，必须人工核对后再决定是否重试。系统不得把该状态报告为成功。点击“重试订单备注和红旗”复用已有入库结果，不重新创建线索；已完整成功但仅上报失败时只重试上报，不再次操作页面。
- 重复订单：返回首次联系人、销售、入库时间和商品审计快照；资料一致时可补齐页面动作，资料不一致时停止。
- 刷新/切换会话、切换店铺、开始新的尝试、关闭面板或退出登录会取消旧尝试并抑制后续成功状态。若页面点击已经发出，取消无法撤销已发生的浏览器动作，因此必须人工核对页面；插件不会继续上报成功。
- 退出会先取消活动尝试。只有后端应用结果`code === 0`且 worker 已完成本地退出才是成功；任何其他应用码或网络异常都保留一致的已登录界面供重试，不会恢复已取消的旧完成尝试。任何请求（包括退出）收到 HTTP 401 时都把它作为终态会话失效：worker 清除 token/操作人，UI同步转为本地退出状态，需重新登录。密码仍不持久化，本机 API 地址和店铺选择仍保留。
