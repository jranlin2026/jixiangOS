# 极享AI浏览器员工 MVP

## 目标

第一版只支持抖店飞鸽客服的固定工作流：

1. 识别当前客户、平台订单号、商品和聊天消息。
2. 从极享OS统一话术库选择内容填入飞鸽回复框，由客服确认后发送。
3. 从客户消息中提取手机号或微信，或由客服补录站外获取的联系方式。
4. 以“平台 + 店铺 + 订单号”作为幂等键，向极享OS创建线索。
5. 线索创建成功后，尝试提交抖店订单备注；失败时保留可重试的备注文本。

插件不会自动发送客服消息，也不会在页面结构未识别时盲目点击。录线索和写备注前都会重新核对当前订单号，客服还必须勾选确认联系方式属于当前订单。

## 话术库和自动推荐

话术库是公司统一配置，保存在极享OS，不是每台电脑各自保存。

- 有线索录入权限的客服可查看和手动填入已启用话术。
- 超级管理员可点击“管理话术”，维护分组、标题、内容、排序、优先级和启用状态。
- 自动匹配条件支持订单状态、商品关键词和联系方式状态。空条件话术仅供手动使用，不会自动推荐。
- 匹配顺序为：优先级、条件精确度、分组排序、话术排序。插件会显示“系统推荐”及命中原因。
- 只有同时识别到订单号和订单状态时才会尝试自动填入。同一订单和话术在一次面板会话中只尝试一次。
- 回复框已有内容时绝不覆盖；所有话术都不会自动点击发送。

管理员保存时使用数据库条件更新和版本号防止多人相互覆盖，且在每次覆盖前保留上一版完整快照。如果收到“已被其他管理员更新”，插件会自动加载最新版本，需重新进入编辑。

## 代码边界

- `apps/browser-extension`：独立 Manifest V3 Chrome 插件，独立安装、测试和打包。
- `server/services/browserAgent`：幂等线索入库和订单备注回执。
- `server/routes/browserAgentRoutes.ts`：浏览器员工专用路由。
- `browser_lead_syncs`：保存跨系统同步状态、平台商品名称和操作留痕，不重复保存客户手机号。

插件不直接写数据库。线索创建继续调用极享OS的 `customerCommandService.createLead`，因此保留原有的权限、联系方式校验、查重、线索来源和销售分配规则。

## 本地构建

```bash
npm --prefix apps/browser-extension install
npm run browser-employee:test
npm run browser-employee:typecheck
npm run browser-employee:build
```

构建产物位于：

```text
apps/browser-extension/dist
```

Chrome 本地加载：

1. 打开 `chrome://extensions`。
2. 打开“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择 `apps/browser-extension/dist`。
5. 每次重新构建后，必须在该扩展卡片上点击“重新加载”，再刷新已打开的飞鸽页面。
6. 打开抖店飞鸽页面，点击插件图标打开右侧面板。

## 极享OS连接

本地默认 API 地址：

```text
http://127.0.0.1:3001/api
```

开发环境允许本地加载的 Chrome 插件访问 API。生产环境必须把已发布插件的精确 origin 加到 `CORS_ORIGINS`：

```env
CORS_ORIGINS="https://os.example.com,chrome-extension://<32位插件ID>"
```

登录密码不持久化。登录后的会话 token 保存在 `chrome.storage.session`，关闭浏览器会话后失效。除本机回环地址外，插件拒绝使用 HTTP 发送账号、密码和 token。

## 飞鸽页面适配

页面实现集中在：

```text
apps/browser-extension/src/content/douyinFeigeAdapter.ts
```

适配器只暴露可审核的读写能力：

- `readContext()`
- `fillReply(text)`
- `fillReplyIfEmpty(text)`
- `appendReply(text, expectedContext)`
- `completeOsOrder(input)`

客户昵称、商品和消息方向已按真实无订单会话校准。2026-08-08 又对一个真实有订单会话做了只读校准，已确认：

- 当前订单卡是包含 19 位订单号的已展开 `role="button"` 区域。
- 订单备注入口是订单卡内文案为“修改”的按钮。
- 备注界面是抽屉，没有 `role="dialog"`；需按“订单备注”、“订单标记”、备注输入框及“确定/取消”的组合语义定位。
- 备注输入框 placeholder 以“请输入备注信息”开头，提交按钮的准确文案是“确定”。

只读校准也确认了三个仍未解决的平台语义：当前只看到已关闭/退款订单，未证明已付款有效订单的状态元素；六个旗帜选项只是无标签的数字 `radio`，没有可证明“绿色”的 `aria-*`、`data-*`、title 或文字；本次也没有获得对安全测试订单的写操作授权，因此未校准保存成功后的页面信号。插件不会猜测订单状态、按 radio 下标或数字 value 猜测绿旗，也不会在未验证成功时报告完成。

未识别时插件会显示诊断结果并停止执行。

## 客服协助式闭环

1. 在飞鸽中打开当前客户的已付款有效订单，在侧边栏点击“刷新识别”。
2. 核对昵称、订单号、订单状态和联系方式；需要时手工补录手机号或微信，并选择联系方式来源。
3. 客服勾选“我已确认昵称和联系方式属于当前订单”，再点击“一键入OS并完成订单”。
4. 分别查看“极享OS入库”、“订单备注”和“绿色旗帜”三个状态。线索入库成功不等于飞鸽页面也已完成。
5. 页面失败时，点击“重试订单备注和绿旗”只会复用已有 `syncId`，不会重复创建线索；备注合并也会跳过已存在的两行。
6. 仍失败时，点击“复制备注”进行人工处理：打开当前订单备注，保留所有历史行，只补齐缺失的 OS 两行，人工选择绿旗后再确认保存。

系统只使用以下 OS 备注格式：

```text
<原有订单备注原样保留>
#<抖音昵称>/<手机号或微信>
#入OS
```

历史备注中已有的 `#入EC` 必须原样保留，但插件绝不会新增 `#入EC`。自动标记的唯一目标是绿旗；无法从页面语义唯一确认绿旗时，必须停止并交由客服手工处理。

## 线索与通知

插件不指定销售，由极享OS线索流转配置决定负责人。

本分支已经合并极享OS统一通知中心。浏览器插件创建线索后，会沿用同一条线索分配事务通知销售、要求确认接收，并按通知规则提醒首次跟进；配置飞书通道后可同时推送飞书。浏览器插件不重复实现另一套通知。

## 已知限制

1. 真实有订单会话已校准当前展开订单卡、订单号、修改入口、备注抽屉、输入框和“确定”按钮；仍需一个明确指定且授权写入的已付款安全测试订单，才能校准已付款状态、绿旗及保存后成功信号。
2. 当前真实绿旗没有可访问名称或稳定语义属性。因此一键流程会在修改备注前停止，提供备注文本、重试和人工处理入口，不会猜测旗帜位置或误报完成。
3. 线索入库依赖极享OS已配置的线索来源、销售参与人员和分配规则。
4. 线索创建与同步状态更新之间若发生中断，会用唯一外部录入键对账原线索；未创建线索的超时任务会在十分钟后释放重试，避免重复和永久卡死。
