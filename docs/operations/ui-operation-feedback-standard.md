# 操作反馈交互规范

## 统一规则

1. 保存、提交、审核、发放、删除、导入、导出、同步、测试连接等用户操作完成后，其成功、失败、警告和结果提示统一使用 `OperationFeedbackDialog`。
2. 禁止使用页面顶部、页面底部或 `Snackbar` 展示操作结果；同一次操作只显示一个结果弹窗。
3. 删除、撤回、重置等高风险操作先使用确认弹窗；执行完成后再显示结果弹窗。
4. 字段必填、格式和表单联动校验保留在字段或当前表单区域，不弹出结果弹窗。
5. 页面加载失败、列表读取失败等持续状态保留在对应内容区，并提供重试入口。
6. 业务说明、范围声明、风险说明、流程提示和当前配置状态保留为页面内信息，不属于操作结果。
7. 导入、导出等多步骤弹窗中的进度、预检、行级异常和字段校验留在当前弹窗；最终操作结果使用统一结果弹窗。

## 组件约定

- 声明式页面使用 `src/shared/components/OperationFeedbackDialog.tsx`。
- 需要 `await alert()` / `await confirm()` 的流程使用 `src/shared/hooks/useAppFeedback.tsx`，其普通提示同样复用统一结果弹窗。
- 结果弹窗默认标题：成功“操作完成”、失败“操作失败”、警告“请注意”、信息“提示”。
- 错误文案必须给出可理解的原因；可以安全重试时应明确提示用户重试。

## 代码门禁

`src/api/operationFeedbackUxStatic.test.ts` 约束统一组件、已迁移页面和全局底部提示，防止后续改动退回到页面边缘提示。
